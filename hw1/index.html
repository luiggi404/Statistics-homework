HW1 — Private key → public key with elliptic-curve scalar multiplication

A toy version of what Ethereum does on secp256k1: from a private number k to a public point Q = kG, plus a statistical look at the outputs.

What this page is about. A public key in Ethereum is a point on an elliptic curve obtained by "multiplying" a fixed base point G by the private key k. Computing Q = kG is fast; going back from Q to k (the Elliptic Curve Discrete Logarithm Problem, ECDLP) is believed to be infeasible on real curves. That asymmetry is what makes it a one-way function.

1. The toy curve

Definition. An elliptic curve over a prime field 𝔽p is the set of pairs (x, y) with 0 ≤ x, y < p satisfying y² ≡ x³ + ax + b (mod p), together with an extra "point at infinity" 𝒪 that acts as the zero of the group.

Ethereum uses secp256k1: y² = x³ + 7 over a 256-bit prime. Here we keep the same equation (a = 0, b = 7) but use a tiny prime so every point can be drawn and checked by hand. With the homework values p = 17, G = (1, 5), k = 6:

  • Check G is on the curve: 5² = 25 ≡ 8 and 1³ + 7 = 8 ✓.
  • The curve has 17 affine points + 𝒪 = 18 points. Since 17 ≡ 2 (mod 3), the curve y² = x³ + 7 is supersingular and always has exactly p + 1 points.
  • G = (1, 5) has order 9: 9G = 𝒪, so G only generates a subgroup of 9 elements (8 points + 𝒪). Private keys are therefore meaningful only modulo 9.

Point addition rules

For P = (x₁, y₁), Q = (x₂, y₂), all operations mod p (division means multiplying by the modular inverse):

P + O = P  and  O + Q = Q            (O = point at infinity)
if x1 = x2 and y1 = -y2:  P + Q = O  (vertical line)
if P != Q:  λ = (y2 - y1) / (x2 - x1)        (chord)
if P == Q:  λ = (3·x1² + a) / (2·y1)         (tangent, "doubling")
x3 = λ² - x1 - x2
y3 = λ·(x1 - x3) - y1                 →  P + Q = (x3, y3)

Geometrically: the line through P and Q meets the curve in a third point −R; reflecting it (y → −y) gives R = P + Q. Over 𝔽p the "line" wraps around modulo p, which is exactly what the animation below draws.

Repeated addition needs k − 1 additions, which is hopeless for a 256-bit key. Double-and-add reads the bits of k from the most significant one: for each bit it doubles the running point and, if the bit is 1, adds G. It needs about log₂k doublings and at most as many additions (≈ 256 + 128 on average for Ethereum keys).

5. Discussion — one-way function vs. hash function

Two different promises. A one-way function only promises: easy to compute, hard to invert. A cryptographic hash function promises much more: arbitrary-length input → fixed-length output that behaves like random bits (uniform bits, avalanche, no exploitable structure), plus preimage, second-preimage and collision resistance.

Conclusion. The statistics that matter for a public-key one-way function are those tied to inversion: determinism, uniformity of Q over the group, and absence of any statistical shortcut from Q back to k. Bit balance, uniformity over all bit strings, avalanche, and "no structure" are properties of hash functions; elliptic-curve scalar multiplication intentionally has structure, and its security comes from the size of the group, not from looking random. Finally, passing simple statistical tests is never proof of one-wayness: the toy curves pass several of them and are still broken instantly by brute force.
